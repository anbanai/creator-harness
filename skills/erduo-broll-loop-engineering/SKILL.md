# Erduo B-roll Loop Engineering

Route the motion package through the available HyperFrames CLI and auditable shot-card JSON. HyperFrames is the only motion runtime for this workflow; do not substitute Shotcraft, Remotion, or an ad hoc runtime installation. Confirm the CLI works and record its observed version; an exact version match is not a workflow requirement. Before rendering, discover supported commands with `hyperframes --help`. If the installed CLI advertises `hyperframes check`, run it and require a passing result. If it does not advertise that command, record a capability gap and block rendering or explicitly mark the run as degraded according to the owning Agent contract; an equivalent check does not silently count as `hyperframes check` passed. Never invent a successful check command. Split work by shot only where the managed runtime supports it, then run the bounded aesthetic review before assembly. Every visual item records its purpose, source and target timecodes, source or generation method, rights state, and dependency on spoken timing. Record slot duration, visual-change count, static hold duration, repeated-asset count and a density-risk summary; use these as warnings for rhythm review, not as a fixed module quota.

Every list/card/relationship graphic uses the incremental reveal contract from `viral-ip-editing`: each item has a spoken anchor, reveal time, order, and before/after visibility state. The first visible frame, order, persistence of prior items, and transition into each item are checked in the sample. Rendering all items in one frame when narration introduces them one by one is a Major defect. Content-driven `camera_motion` is likewise tied to a spoken anchor and reason; sample review verifies that planned push-in, pull-out, reframe, or snap-to-anchor motion exists in the rendered frames.

The first deliverable is a review sample. Do not add sound effects or BGM before the sample is approved by the Server review gate. Do not force unused assets into a timeline or add factual claims that are absent from the source. If an asset's purpose is unclear, leave it for review and record the uncertainty. Missing runtime dependencies are blocking failures; do not silently use `video-edit` as a fallback.

Run HyperFrames lint before each sample render and use the fixed remediation table in [references/hyperframes-lint.md](references/hyperframes-lint.md). A clean lint and a passing advertised runtime/layout check are prerequisites for managed rendering. If the check capability is missing, record `capability_gap` and stop managed rendering, or follow the owning Agent's explicit local-test degradation contract. Do not claim an equivalent check or a self-review is an independent aesthetic review. Review the opening, card, transition, and ending frames with the tools that are actually available; if no independent reviewer or registered video-analysis capability exists, mark the evidence `self-review/degraded`, record the concrete limitation, and do not label it independently approved. Do not assume an `analyze_video` command exists.
