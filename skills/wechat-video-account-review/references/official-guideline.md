# 视频号官方规则整理

来源：微信官方《视频号常见违规内容概览》：<https://weixin.qq.com/cgi-bin/readtemplate?lang=zh_CN&t=weixin_agreement&s=video_guide#13>

本文件是面向视频制作的检查摘要，不替代官方页面。官方页面更新时，以最新页面为准；无法确认规则版本时，应记录 `unavailable`，不要假定符合。

## 分类矩阵

| 官方分类 | 计划和成片中要检查的高风险信号 |
| --- | --- |
| 1. 账号违规 | 违规账号资料、重复发布违规动态、违规私信骚扰、无资质发布风险内容、恶意留联系方式。Agent 不修改账号状态；发现输入涉及这些行为时阻断或标记。 |
| 2. 侵权内容 | 未授权使用他人肖像、隐私、名誉、著作权、商标或商业秘密；未经授权搬运、录屏、保留他人水印或只做裁剪/镜像/变速/加边框等低成本二创。 |
| 3. 低俗内容 | 低俗、恶俗、恶意猎奇、令人不适的语言、画面、动作、标题或包装。 |
| 4. 过度营销或骚扰他人内容 | 传销、无资质募捐、违规软件/服务、医疗或保健营销、搬运引流、纯营销、风险产品、煽动性售卖和骚扰式联系方式。 |
| 5. 违法违规或令人不适内容 | 违法犯罪、危险行为、暴力血腥、毒品赌博、恐怖极端、伤害未成年人/动物以及其他违反法律或造成明显不适的内容。具体边界以官方页面最新文本为准。 |
| 6. 诱导性质内容 | 以虚假利益、夸张承诺、强制互动、虚假任务或其他方式诱导用户点击、关注、点赞、评论、转发、私信或参与活动。 |
| 7. 色情内容 | 色情、露骨性暗示、性服务或聚焦隐私部位；检查真人、生成画面、封面、字幕、配音和文案，不以“艺术”名义绕过。 |
| 8. 滥用功能内容 | 利用平台功能骚扰、刷屏、恶意举报、批量灌水、规避审核或干扰其他用户正常使用。 |
| 9. 不实、夸大、误导、虚假内容 | 虚假事实、夸大效果/销量/排名、绝对化用语、无法证明的专家或机构背书、价格/赠品/活动不一致、虚构商品/服务和误导性对比。 |
| 10. 无资质发布有风险内容 | 医疗、金融、教育、法律、食品、保健、医美、投资等需要资质或专业依据的内容；核对资质、适用范围、证据和表达边界，不能用免责声明掩盖无资质营销。 |
| 11. 虚假作弊行为 | 虚构播放量、点赞、评论、转发、成交、排名或用户反馈；购买/组织虚假互动，或用剪辑和画面伪造真实参与。 |
| 12. 同质化行为 | 抄袭或高度重复他人作品、模板化搬运、低信息增量的拼接和只改字幕/画幅/颜色/速度的重复发布。 |
| 13. 欺诈、可疑、不诚信等内容或行为 | 见下节。该分类对联系方式、外部导流和财产损失风险执行高优先级检查。 |
| 14. 违背公序良俗 | 违背社会公德、公共秩序、基本伦理或造成不良示范的内容和行为。 |
| 15. 视频制作缺陷，影响用户体验 | 黑帧、花屏、严重卡顿、画面/声音缺失、字幕不可读、音画不同步、过度遮挡、低清晰度或其他影响理解和正常观看的缺陷。 |
| 16. 其他违规 | 以上未覆盖但违反平台规则、法律法规或平台处置要求的内容；发现不确定风险时保守标记，不用分类缺失作为放行理由。 |

## 第 13 类原文要点的制作化检查

官方页面的 `#13` 标题为“欺诈、可疑、不诚信等内容或行为”，页面列出的要点包括：

1. 利用隐瞒、诱骗、发布虚假内容等手段欺诈用户，可能使用户财产等遭受损失。
2. 出现风险不可控的联系方式，包括电话号码、二维码等。
3. 引流到视频号外平台，风险不可控；示例包括明确提及其他平台账号信息、引导去其他平台搜索或观看、包含其他平台链接或二维码、提及其他平台同款商品等。

把要点落到剪辑检查时：

- 逐字检查口播、字幕、封面和画面文字中的价格、收益、赠品、活动期限、中奖、联系方式和购买指令；每项都要有当前版本证据。
- 逐帧检查二维码、电话号码、社交账号、评论区/私信指令和画面角落的导流信息；检查实际跳转目标及授权，不清楚就阻断。
- 检查“去某平台搜索/看完整版/同款在某平台”等口播、字幕、贴纸、评论置顶和封面暗示；没有明确合规依据时删除或改写。
- 对“保证赚钱、稳赚、零风险、内部渠道、最后机会、官方/专家推荐”等可能造成财产损失或虚假信任的表达，要求证据、降低承诺或阻断。

## 证据与严重度

- `blocker`：涉嫌欺诈、财产损失、风险联系方式/外部导流，严重侵权，违法或无法播放；不得生成或交付。
- `major`：无法证明的营销/效果主张、无资质高风险领域、明显诱导或大规模同质化；修订后重审。
- `minor`：不改变含义且不影响发布的低风险表达或技术细节；记录并在时间允许时修复。

缺少来源、授权、资质、价格/活动证据或可靠的官方规则读取结果时，使用 `missing`/`unavailable` 记录缺口；不要凭“常识”补齐证据。
