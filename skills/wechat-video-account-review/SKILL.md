# 微信视频号审核

这是一个平台规则预审 Skill，不是法律意见，也不代表微信最终审核结果。规则来源为微信官方的[视频号常见违规内容概览](https://weixin.qq.com/cgi-bin/readtemplate?lang=zh_CN&t=weixin_agreement&s=video_guide#13)，页面内容可能更新；本 Skill 的整理版本以任务读取官方页面时的内容为准。详细分类见 [official-guideline.md](references/official-guideline.md)。

## 适用范围

审核视频号作品的计划和实际产物，包括：

- 口播脚本、标题、正文、字幕、封面文案和 CTA。
- 真人画面、B-roll、AI 生成画面、图表、动效、贴纸、二维码和联系方式。
- 配音、配乐、音效、背景噪声及其版权/授权记录。
- 计划或实际出现的商品、服务、价格、效果、资质、机构/专家背书和外部平台引导。

不要把本 Skill 当成泛化的“内容好不好看”评分器；它负责识别平台风险、证据缺口和必须在制作前修正的计划问题。

## 评审时机

审核必须前置，不能等成片生成后才第一次检查：

1. **Plan Review 闸门：** 在生成 B-roll、AI 视频、复杂包装、配乐，或开始渲染前，检查已校对的脚本/转录、Hook、标题、字幕计划、封面计划、CTA、联系方式、二维码、外链、商品/服务主张、素材来源和授权状态。存在高风险、不可证实主张、风险联系方式或外部导流时，先改计划并重新审核。
2. **重大修订复审：** 结构、文案、Hook、画面、字幕、封面、声音、CTA、联系方式、二维码、外链或素材来源发生变化时，只要影响到相关检查项，就在下一次高成本制作前重跑受影响范围；不能沿用旧版“通过”。
3. **成片复核：** 在实际导出后再核对视频、封面和交付文案，确认计划中的修复确实落地。它是第二道防线，不是替代前置闸门。

## 评审方法

1. 固定当前 `project_id`、`task_id`、`revision_id` 和输入/成片路径。将计划证据与实际成片证据分开记录。
2. 先检查高影响的事实、权利、联系方式、导流、营销和危险内容，再检查同质化、诱导互动和制作缺陷。
3. 对每个命中项记录规则编号、证据位置（转录时间码、画面时间点、文件路径或文本片段）、风险等级、原因和最小修复动作。没有足够证据时标记为待核验或不可用，不自行推断通过。
4. 计划阶段只允许使用用户素材或已明确授权/待核验的素材。待核验不等于已授权，也不等于可以交付。
5. 修复后重新检查相关项，并确认 `edit_master_plan.md`、`plan_review.md`、视觉/声音计划和修订记录已经同步。

## 必查重点

- **真实性与权利：** 不伪造真人、商品、实验、数据、专家/机构背书或新闻事实；检查肖像、隐私、著作权、商标、音乐、字体、素材水印和二次创作的信息增量。
- **营销与主张：** 价格、赠品、销量、排名、效果、资质、活动期限和购买条件必须能由当前任务证据支持；避免绝对化、夸大、虚假稀缺、虚假权威和医疗/健康等高风险功效承诺。
- **账号与互动：** 不安排骚扰、刷量、虚假互动、恶意引导、违规软件/服务或高风险账号行为；不要用“点赞、关注、转发、评论、私信”承诺利益来规避审核。
- **内容安全：** 排除色情、低俗、暴力、违法犯罪、赌博、毒品、危险行为、伤害未成年人、动物虐待、违背公序良俗及其他会令人不适或构成违法风险的内容。
- **制作质量：** 成片不得出现黑帧、冻结、严重闪烁、不可读字幕、画面/声音缺失、过度噪声、明显音画不同步或遮挡平台界面的二维码/文字。质量缺陷影响理解时按阻断项处理。

## 链接所指的第 13 类

官方页面 `#13` 为“欺诈、可疑、不诚信等内容或行为”，至少逐项检查：

1. 是否通过隐瞒、诱骗或发布虚假内容，使用户可能遭受财产等损失。
2. 是否出现风险不可控的电话号码、二维码或其他联系方式；用途、归属、跳转目标和安全性是否有证据。
3. 是否引流到视频号外平台，包括明确提及其他平台账号、引导去其他平台搜索/观看、放置其他平台链接或二维码，或提及其他平台同款商品。没有明确业务授权和可核验证据时，按高风险处理。

## 结论与产物

将结果写入：

- `output/wechat-video-account-review-plan.md/json`：Plan Review 前置闸门的独立证据。
- `output/wechat-video-account-review-revision-<revision_id>.md/json`：重大修订复审的独立证据；每次新修订使用唯一 `revision_id` 文件名，追加登记，不得覆盖计划或其他修订证据。
- `output/wechat-video-account-review-final-<revision_id>.md/json`：实际成片和封面复核的独立证据；每个导出修订使用唯一 `revision_id` 文件名，不覆盖历史 Final Review。
- `output/wechat-video-account-review.md/json`：只作汇总索引，登记计划文件、全部修订文件、最终文件、各阶段状态、`revision_id` 和证据路径；不得用汇总文件替代阶段文件。

每个阶段 JSON 至少包含 `schema_version`、`status`、`source`、`authority_url`、`checked_at`、`stage`、`revision_id`、`findings`、`missing` 和 `evidence_paths`。计划证据与实际成片证据必须分开保存，保证能够审计前置审核先于高成本制作发生。

`status` 只能使用：

- `passed`：本阶段检查完成，没有未处理的高风险项。
- `needs_revision`：发现可明确修复的问题；修复并重跑相关检查后才能继续。
- `blocked`：命中严重风险、关键事实/授权无法成立，或计划/成片不应继续。
- `unavailable`：官方规则或必要证据无法可靠读取；在计划闸门阶段不得继续高成本生成。

修订阶段和 Final Review 的 `revision_id` 必须同时出现在文件名和 JSON 字段中；同一项目的后续修订只能新增文件，不能覆盖已有阶段证据。只有当前修订的审核 JSON 为 `passed` 且没有未处理的 `blocker` 或 `major`，才允许进入下一次高成本生成或渲染。

`findings[].severity` 使用 `blocker`、`major`、`minor`；`blocker` 和未解决的 `major` 不得进入生成或交付。不要把“未发现”写成“平台保证通过”，也不要把自动文字扫描替代画面、声音、语义和权利核验。
