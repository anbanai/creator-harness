# Generated Video Asset Contract

`output/generated-video-manifest.json` is a revision-bound record of actual successful generation results. Each `items[]` entry must contain:

- `asset_id`: stable non-empty identifier.
- `kind`: exactly `ai_video`.
- `path`: task-relative generated video path under `output/`.
- `sha256`: hash of the exact generated bytes.
- `generation`: `status="succeeded"`, provider, model, request ID, generation time, and parameter object.
- `purpose`: explanation unit ID and the visual function the motion serves.
- `review`: `status="approved"`, reviewer/method, reviewed time, inspected range, and current revision ID.
- `revision_id`: the revision that owns the asset and review.

The current `output/edit-decision-list.json` must reference each required asset from a segment's `visual_assets[]` entry with matching `asset_id`, `kind="ai_video"`, `purpose_unit_id`, and a positive output frame interval. At least one required item must map to a core explanation unit. EDL output intervals define placement; generated-asset source intervals define trimming. They must not be conflated.

The manifest top level must include `schema_version`, `revision_id`, `source="talking-head-video-generation"`, and `items`. The validator writes `output/generated-video-lint.json` with recomputed input hashes and per-asset results. This proves only that the declared evidence is internally consistent and an approved generated asset is referenced by the EDL; it does not authenticate provider execution, reviewer identity, or renderer inclusion in the final MP4. Final-render presence must be checked in the independent final-media review; this validator does not measure it. `video-production-qc` must rerun the asset validation against the current files and EDL; it must not trust the lint JSON alone.

Each EDL visual reference also declares `source_in` and `source_out` in generated-asset seconds. Run `python3 scripts/validate_generated_video.py --manifest output/generated-video-manifest.json --edl output/edit-decision-list.json --revision-id <revision> --root . --output output/generated-video-lint.json`. Generation metadata is a traceable provider record, not cryptographic provenance.
