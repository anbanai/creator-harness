## 这份参考解决什么问题

公众号正文图的任务是帮助读者继续读懂文章，而不是重复封面的点击承诺。工业级 prompt 的关键不是堆叠“高级、电影感、精致”等形容词，而是把章节证据、阅读动作、版式和媒介拆成可观察的约束，并让审核结果能回指到这些约束。

正文图每张都应有以下九个槽位：

1. **slot 契约**：`hero`、`section_opener`、`inline_detail` 或 `footer`，它在正文阅读流中的职责、目标章节和有效比例。
2. **页面目标**：读者看到图片后应完成的一个理解动作，例如识别一个过程、比较两种状态或记住一个具体场景。
3. **文字契约**：默认无字；若是信息图、流程图或清单图，列出逐字可见的文字白名单、层级、位置和安全区。
4. **章节证据**：`visual_brief`、`required_entities`、`must_match_excerpts`、主体状态和实体关系；只使用当前章节的信息。
5. **构图地图**：镜头、景别、焦点区域、文字区域、留白、信息块排列和阅读顺序。
6. **艺术指导**：媒介、表面材质、色板、字体/标签气质、图标和批注语言。
7. **光线与材质**：光线方向、色温、阴影、景深和需要被看清的物理细节。
8. **系列连续性**：继承的风格锚点，以及本张必须变化的主体、视角、场景或色彩重心。
9. **负面约束与验收**：不得带入的其他章节信息、额外文字、导流元素、主体幻觉和可观察的通过条件。

缺少一个关键槽位，比少写几十个同义风格词更容易让正文图失去章节相关性。`ref_image_path` 只能传递封面或项目的风格语言，不能代替本页的章节证据。

## 何时读取

在 `image-plan.md` 为每个需要生成的 slot 写完字段后读取一次；在写 `image-prompts.md`、调用 `generate_image` 和构建 `analyze_image` 审核 prompt 前再次对照。封面由 [article-cover-design](../../article-cover-design/SKILL.md) 及其 references 管理，不把正文图的章节模板套到封面上。

## 编译顺序与优先级

最终 prompt 按下面顺序组织，硬约束应先于风格修饰：

```text
slot 与页面目标 → 文字契约 → 构图地图 → 章节证据与主体关系
→ 艺术指导 → 光线与材质 → 跨页连续性 → 负面约束 → 输出与验收
```

冲突时按以下优先级处理：

1. 用户锁定的比例、章节事实、主体、可见文字和禁止项。
2. `visual-rhythm-plan.md` 的 slot、`image-plan.md` 的页面职责和验收标准。
3. 文章正文中可追溯的 `must_match_excerpts`。
4. 手机阅读的可读性、构图安全区和平台展示派生。
5. 项目视觉风格、参考图提炼的媒介和色彩。
6. 可选的氛围形容词。

不要把整篇文章或其他章节的原文塞进一个 prompt。每张只传当前 `page_scope`；对于不在本页的产品、人物、季节、数据和结论，明确写入 `out_of_scope`，防止模型串页。

## 页面目标与阅读动作

`page_goal` 必须是一个可以观察的阅读动作，不写“营造高级感”。可用的动作包括：

| slot / 页面类型 | 典型目标 | 常用画面策略 |
| --- | --- | --- |
| `hero` | 让读者在进入正文前建立文章核心场景 | 一个主焦点、证据化隐喻、留出标题/正文衔接空间 |
| `section_opener` | 让读者知道本章讨论的具体对象或冲突 | 章节实体为第一焦点，背景只承担上下文 |
| `inline_detail` | 放大一个动作、材质、案例或关键细节 | 特写、局部关系或过程中的一个可验证瞬间 |
| `footer` | 收束已讲过的结论或情绪 | 只使用正文已经出现的主体，不新增事实或导流文字 |

一张图只承担一个主要阅读动作。章节有多个论点时，按模板拆成多张，或用明确的卡片/流程布局绑定每个信息点；不要用一张“相关物件大合照”代替信息结构。

## 文字契约

公众号文章正文图默认**无字**，让 HTML 正文承担完整解释。只有信息图、流程图、对比图或用户明确要求的栏目图才允许带字：

- `visible_text_whitelist` 逐条记录实际需要出现的简体中文，按最终阅读顺序用全角引号「」包裹；不得改字、拆句、改标点或同义改写。
- `text_policy` 写明“无字”或“受控短标签”；若无字，模型不得补标题、页码、品牌名、书页字、水印或伪词。
- 文字区域必须有连续背景、足够对比和移动端字号；写清 `text_zone` 与主体的避让关系。
- 审核要同时检查逐字准确、顺序、遮挡、缩略图可读和白名单外文字。prompt 里 `1.`、`2.` 等元编号不等于画面文字。
- 任何二维码、联系方式、外链 URL、扫码提示、加群、加微信、关注领资料或回复关键词都判为失败。

模型不能保证多行中文逐字准确。若运行环境没有独立叠字能力，必须由 `analyze_image` 逐字观察；关键文字错误时重写布局/减少装饰后重试，耗尽预算则记录 `quality_status=failed`，不得仅凭 prompt 宣称通过。

## 构图地图

每个 slot 至少填写下表字段，使用相对区域即可，不要求像素级坐标：

| 字段 | 要回答的问题 |
| --- | --- |
| `camera` | 俯拍、平视、三分之四视角、侧面还是局部微距？ |
| `shot` | 环境全景、桌面中景、人物半身、物件组还是细节特写？ |
| `focal_area` | 第一眼看到什么，位于左/中/右、上/中/下哪个区域？ |
| `text_zone` | 若有字，字放在哪里，哪里必须保持干净？无字时写主体保护区。 |
| `layout_map` | 单焦点、前中后景、对比双栏、流程、卡片还是标注关系？ |
| `negative_space` | 哪些区域保持留白，避免主体、文字或装饰侵入？ |
| `reading_order` | 从主体到细节，或从左到右/上到下，读者如何扫视？ |

`composition_type` 只是类型名，不能代替地图。例如“对比双栏”必须写明左/右各自代表什么；“流程图”必须写清步骤节点和方向；“三分法”必须点名主体落在哪个交点、留白服务什么。

## 章节证据、主体状态与关系

把抽象的 `visual_subject` 拆成可见事实：

- `visual_brief`：1–2 句白话，陌生设计师能据此画出同一场景。
- `required_entities`：能直接观察到的具体物体、人物、环境或图形，不写“氛围”“高级感”。
- `subject_states`：打开/关闭、干燥/潮湿、破损/完整、正在进行/已完成等可见状态。
- `subject_relations`：哪个物件对应哪条论点、谁在做什么、前后关系和对比关系。
- `must_match_excerpts`：章节原文中支撑这些事实的句子；不能凭空补充数字、功效、人物身份或产品属性。

例如“说明保存方式”不能只写“茶罐、冰箱、香料”，而应写成“密封茶罐在避光柜内，绿茶冷藏盒单独放置，香料柜与茶罐保持可见距离；画面不表现串味已经发生”。

## 艺术指导、光线与连续性

艺术指导只保留会改变画面的信息：

- **媒介与表面**：摄影、编辑设计、插画、水彩、纸张或木桌等，选择一个主媒介，避免把“真实摄影”和“水彩插画”当成同一层无条件叠加。
- **色彩**：3–5 个主色/强调色，以及主体如何从背景分离；不要只写“高级灰”。
- **光线与材质**：方向、软硬、色温、阴影和要被看清的材质细节。
- **版式语言**：只有确实使用信息图时才写网格、卡片、编号、标签或批注；摄影/氛围图不要生成伪杂志文字。

跨页连续性要分成两句：

- `series_anchors`：整篇保留的媒介、表面、色彩、线条或光线锚点。
- `page_variation`：本页相对上一页必须变化的主体、景别、视角、动作或色彩重心。

连续三张正文图不得复用同一主物件、同一远近景或同一色块重心；`listicle` 可以保持版式秩序，但每章的章节证据仍必须变化。

## 可复用的最终 prompt 骨架

空字段删除，不要写“无”：

```text
页面契约：这是公众号文章《{article_title}》的 {slot_id}，服务章节《{chapter_title}》，页面目标是 {page_goal}。最终画布比例严格为 {aspect_ratio}，用于手机正文阅读，展示尺寸为 {image_size}。

文字契约：{text_policy}。画面只允许出现以下可见文字，按顺序逐条原样渲染：{visible_text_whitelist}。文字/主体安全区为 {text_zone}；不得出现白名单之外的字母、拼音、数字、页码、书页字、品牌、水印、伪词或导流信息。

构图地图：{camera}，{shot}；第一焦点是 {focal_area}；{layout_map}；保留 {negative_space}；阅读顺序为 {reading_order}。

章节证据：{visual_brief}。必须出现：{required_entities}。它们的可见状态为 {subject_states}，与本章论点的关系为 {subject_relations}。只使用当前章节的 {page_scope}，不得引入 {out_of_scope}。

艺术指导：主媒介与表面为 {medium_surface}；系列风格锚点为 {series_anchors}；本页变化为 {page_variation}；色彩为 {palette}。

光线与材质：{lighting}；重点表现 {material_details}，让主体与背景分离。

禁止项：{negative_constraints}。不得复刻封面主体、封面构图或其他章节的物件和结论。

输出验收：{acceptance_criteria}。画面清晰、关系可见、移动端缩略图仍能完成页面目标；生成后由独立视觉审核确认。
```

## `image-plan.md` 建议字段

每个正文 slot 除既有字段外，建议使用下面的结构；空字段不填：

```markdown
## img_01 章节：{chapter title}
- slot_id: section_opener
- section_index: 1
- chapter_title: {章节标题}
- core_point: {本章核心论点}
- page_goal: {读者看完图要完成的理解动作}
- page_scope: {只允许使用的章节事实/段落范围}
- composition_type: {类型名}
- camera: {镜头}
- shot: {景别}
- focal_area: {第一焦点与区域}
- text_policy: {无字 / 受控短标签}
- visible_text_whitelist: [{按最终阅读顺序逐字列出}]
- text_zone: {文字或主体保护区}
- layout_map: {布局与信息块关系}
- negative_space: {留白区域}
- reading_order: {阅读顺序}
- visual_brief: {可直接画出的白话场景}
- required_entities: [{具体实体}]
- subject_states: [{实体状态}]
- subject_relations: [{实体与论点的关系}]
- must_match_excerpts: [{章节原句}]
- medium_surface: {媒介与表面}
- palette: {主色与强调色}
- lighting: {方向/色温/软硬}
- material_details: {要看清的材质}
- series_anchors: {整组共享锚点}
- page_variation: {本页变化}
- out_of_scope: [{不得出现的其他章节内容}]
- anti_generic_constraints: [{避免模板化的具体约束}]
- acceptance_criteria: [{可观察验收条件}]
```

这些字段是 prompt 的来源，不要求全部原样复制到文章正文或 HTML；`images.json` 应保存最终 prompt 和关键字段，便于复盘图文是否漂移。

## 生成前检查

- 这张图是否只有一个主要页面目标，并与 `slot_id`、章节标题和 `chapter_anchor` 一致？
- `visual_brief`、`required_entities`、状态和关系是否能从当前章节原句追溯？
- 是否写清镜头、景别、焦点、文字/主体保护区、布局地图和阅读顺序？
- 文字白名单是否为空或逐字完整，是否明确禁止模型补写？
- 是否只使用当前 `page_scope`，并排除了其他章节的主体、数字、季节和结论？
- 共享风格是否被压缩成稳定锚点，本页是否有真实可见的变化？
- prompt 中是否显式保留 `$EFFECTIVE_ASPECT_RATIO`，而没有用固定比例或隐式裁剪替代？
- `analyze_image` 是否能逐项检查实体、关系、构图、文字、合规和页面目标？

只有这些问题能从最终 prompt 和审核记录中回答时，才把图片标记为可用。
