# 视频 BGM 设计（video-bgm-design）

BGM 是宏观情绪建筑，不是一条循环铺满全片的音轨。它有自己的判断（哪一章用什么情绪、什么时候换曲、换曲怎么接）、自己的素材契约（授权、来源、哈希）和自己的验收（覆盖、连续、不压人声、换曲不刺耳）。本 Skill 是这些规则的唯一来源；Agent 负责阶段编排和文件路径，音效（SFX）由音效 Skill 负责，字幕由 `video-subtitle-design` 负责。

默认单曲贯穿；只有情绪、能量、空间或章节语义确实变化时才换曲。换曲必须写明理由、接法和受影响的时间段。

## Pixabay 音乐能力

BGM 搜索只使用随 Anban 分发的本地 `search-pixabay` Skill 生成 Pixabay 音乐候选链接；不要求安装外部插件或 MCP。该 Skill 只生成链接，不下载音频或核验授权。运行环境可用的浏览器、下载或授权核验能力须在本次任务中实际探测；不得假设它们存在。只有取得本地音频文件，并记录可核验的来源与许可信息、访问时间及 SHA-256，曲目才可进入混音。若环境无法完成这些步骤，保留候选并写 `resume_from=bgm_selection`，不进入混音，也不转去其他来源找替代曲目。用户提供或项目既有音乐库中的本地曲目可按本 Skill 的来源与授权合同审核；这不授权使用其他搜索渠道。

## 适用范围与边界

负责：整片情绪弧、章节/场景到 track 的映射、cue 起止与换曲点、曲目选择标准、授权与来源证据、多曲拼接与转场、自动 ducking 与响度、BGM 覆盖与 QC。

不负责：SFX（音效 Skill）、字幕（`video-subtitle-design`）、剪辑结构与镜头（剪辑规范）、发布与版权申诉、Server 任务状态。

硬性边界：

- 只通过本地 `search-pixabay` Skill 生成 Pixabay 候选；本工作流不通过其他站点或通用网页搜索发现 BGM。该 Skill 本身不下载或核验授权。若没有运行时明确提供的授权获取能力，保留候选并标为待取得，不将 BGM 阶段伪报为完成；授权未核验的曲目不得进入成片。
- 不得用音乐替代内容：没有信息增量的音乐只增加干扰。
- 不得用持续升调、密集打击乐制造虚假紧迫感或掩盖内容空洞。
- 不得声称任何曲目“已获平台授权”或“一定过审”；只陈述可核验的许可证事实。

## 输入

必需：

- 成片时长与章节/场景划分（章节 id、起止、用途、情绪目标；可由剪辑计划提供）。
- 干净人声母版（或人声时间轴），用于判断 ducking 和音乐留白。
- `output/bgm-candidates.json`（由 `search-pixabay` 生成）中的候选链接，以及（若已取得）本地音频文件和来源/许可信息；候选不等于可用素材。

可选：

- 项目品牌音乐偏好（风格、禁用乐器、禁用歌词）。
- 历史片子的 BGM 选择（用于一致性，不用于复用未授权素材）。
- 平台响度要求（没有则使用默认目标并在产物中标注）。

缺少章节划分时，按语义段自行划分并写明依据；缺少授权信息时，按失败合同处理，不得先混音后补授权。

## 第一步：画情绪弧

先写“情绪弧”，再挑曲子。情绪弧以章节为最小单位，输出到 `output/bgm-plan.md` 的叙事部分（或 `bgm-plan.json` 的 `arc[]`）：

1. 用一句话概括整片情绪走向，例如“好奇 → 怀疑 → 释然 → 行动”。
2. 为每个章节写：`purpose`（Hook/主体/案例/转折/结论/CTA）、`emotion`（2–3 个词）、`energy`（低/中/高）、`tension`（建立/维持/释放）、`voice_density`（口播密度：高/中/低）。
3. 标注“必须让位给人声”的段落（密集口播、关键数字、免责声明）和“可以抬高”的段落（无口播的画面段、转场、结尾）。
4. 标注“需要留白”的段落：重大结论、情绪峰值、金句前可以完全停音乐 1–2 秒，留白比加音乐更有力。

情绪弧必须与剪辑计划和口播内容一致；不得为了用某首曲子而改变叙事。

## 第二步：决定换曲策略

四选一（可以混用，但必须写清楚每段用哪种）：

| 策略 | 适用 | 代价 | 记录要求 |
|---|---|---|---|
| 单曲贯穿 | 时长 < 60 秒、情绪单一、口播为主 | 听到后段容易疲劳 | 记录 loop 边界与重复处理 |
| 一章一曲 | 章节情绪差异明显（如 Hook 紧张、正文温和、结尾昂扬） | 换曲点多，接法要求高 | 每章记录 track 与换曲理由 |
| 基础曲 + 章节变奏 | 同一主题不同段落（如主歌/副歌/纯器乐版） | 需要同源变奏素材 | 记录变奏来源与对应关系 |
| 留白 + 点状音乐 | 口播极密或情绪极重 | 需要更强的节奏控制 | 记录静音段与再入点 |

换曲判定（满足任一即可换，不要为换而换）：

- 章节用途变化（Hook → 主体、主体 → CTA）。
- 情绪方向反转（紧张 → 释然、怀疑 → 确定）。
- 能量等级跨两级（低 → 高，或高 → 低）。
- 时间/空间跳转（换场景、换地点、闪回）。
- 口播密度骤变（密集讲述 → 纯画面段）。

不建议换曲：

- 同一章内每隔十几秒换一次（碎、廉价）。
- 只为了“不重复”而换（观众感知不到，只留下突兀）。
- 换曲点正好压在关键数字或免责声明上。

换曲数量参考：60 秒内通常 1 首；60–180 秒通常不超过 2 首；超过 180 秒按章节数控制，每章最多 1 次换曲。数量只是上限，不能为了覆盖上限而增加曲目。

## 第三步：选曲

将 `output/bgm-candidates.json` 中的候选按原始 `candidate_id`、标题、作者、曲目页 URL、检查时间和适配说明复制到 `bgm-plan.json.candidates[]`，并保持 `candidate_only: true`。未取得本地音频和权利凭证的候选不得进入 `tracks[]` 或 `cues[]`。对已取得且核验的曲目，再按以下维度选择，写入 `bgm-plan.json` 的 `selection`：

- **情绪**：与章节 `emotion` 匹配，优先“支撑”而不是“重复”。悲伤段不必用悲情大提琴，克制的钢琴可能更准。
- **能量**：用配器密度与鼓点强度对齐 `energy`；能量错配比情绪错配更明显。
- **BPM**：与剪辑节奏相关但不强绑。快剪段落不要用极慢曲；慢段落不要用 140BPM 以上。
- **配器**：避免与人声频段冲突（大量中频弦乐、密集人声采样会压口播）。
- **歌词**：口播段落默认避开有歌词的曲子；纯画面段可用，但歌词语言要与受众一致，且不得与口播语义冲突。
- **结构**：优先选有明确 intro/loop/outro 的曲子，便于在换曲点干净收尾；无 intro 的曲子需要淡入。
- **时长**：单曲可用长度必须覆盖 cue 时长；不足时用 loop，并记录 loop 边界是否可听出接缝。
- **片段选择**：不得默认每个 cue 都从 `in_point=0` 开始。按当前章节的乐句、节拍、能量包络和转场目标选择 `in_point`/`out_point`；多个 cue 复用同一曲目时，除非是刻意设计的主题回归，否则不得重复同一音乐片段或相同开头。为每个复用点记录音乐源区间、选择理由和与相邻画面/章节的关系。
- **候选可追溯性**：记录所选候选的搜索关键词、Pixabay 搜索链接和候选状态，便于后续取得文件后继续核验；不要将未取得的候选登记为已选 track。

## 第四步：授权与来源

每首曲目必须有一条可核验的来源记录，写进 `bgm-plan.json` 的 `tracks[]`：

- `track_id`、`title`、`artist`、`duration_seconds`。
- `source_type`：`user_provided` / `project_library` / `pixabay_verified`。不得创建其他来源类型；不能归入这三类的曲目不进入本流程的选曲与混音。
- `source_ref`：授权库条目 id、订单号或用户提供的文件名；不得写密钥、cookie 或内部 URL。
- `license`：许可证名称与关键限制（是否可商用、是否需署名、是否限平台）。
- `sha256`：曲目文件哈希。
- `rights_status`：`verified` / `unverified` / `rejected`。

规则：

- `rights_status != verified` 的曲目不得进入成片；`unverified` 只能出现在候选清单里。
- 同一首曲子跨多个 cue 使用时只登记一次 track，cue 引用 `track_id`。
- 需要署名的许可证必须在 `bgm-plan.md` 给出署名文案，供发布时使用。
- 用户要求先搜索网络素材不代表放弃授权门禁；无法核验使用权时只能保留候选记录，不得混入成片。

## 第五步：拼接与转场

换曲不是把两条音轨首尾相接。按下列顺序选择接法，并写入 cue 的 `transition_to_next`：

1. **同源变奏切换**：同一曲目的不同段落，直接按乐句边界切换（最干净）。
2. **同调或近关系调 + BPM 差 ≤ 8%**：短交叉淡化（0.4–0.8s），在乐句结束处切换。
3. **BPM 差 8%–20%**：在强拍或段落收尾处硬切，配 60–120ms 淡入淡出防止爆音；或用 riser/whoosh 类转场音效桥接（转场音效由 SFX Skill 负责，这里只记录 cue 点）。
4. **BPM 差 > 20% 或调性冲突**：必须用过渡手段——留白 drop（0.5–1.5s 静音后新曲进入）、转场音效、或让新曲从 intro 进入。禁止直接硬接。

通用规则：

- 换曲点必须落在剪辑点或章节边界，不得落在句子中间。
- 换曲点不得压住关键数字、免责声明、结论句。
- 每次换曲做 3 秒复听：有无爆音、音量跳变、节奏错位、调性打架。
- 单曲 loop 时记录 `loop_points` 与接缝处理；接缝可听出时必须换曲或改用变奏。
- 音乐提前退出（fade out）时长 0.5–2s，避免突然静音；结尾淡出通常 1.5–3s。

## 第六步：与口播混音

人声永远优先。

- 口播段落的音乐增益：相对人声 -12dB 至 -18dB；密集数字/条款段可到 -20dB。
- 无口播的画面段可以让音乐升到 -6dB 至 -10dB，但同一章内不得频繁上下跳。
- 使用自动 ducking：`attack` 80–150ms，`release` 250–500ms；不要在每句话之间抽吸，按语义段落触发。
- 频段避让：人声 1–4kHz 是清晰度关键区，音乐在此区间做 2–3dB 的宽 Q 衰减；不要把整条音乐简单压成闷音。
- 响度：以整片积分响度为准，默认目标 -14 LUFS（平台无要求时），真峰值不超过 -1 dBTP；记录测量方法与设备。
- 测量必须包含：整片积分响度、真峰值、每个 cue 的峰值、换曲点前后 3 秒的响度差（建议 ≤ 3 LU）。
- 音量自动化不得造成“音乐忽大忽小”的听感；每次调整都写入 cue 的 `gain_db` 与 `ducking`。

## 第七步：与字幕、音效、画面的关系

- **字幕**：音乐不得压过字幕所对应的口播；音乐重拍不得驱动字幕时间（字幕由 `video-subtitle-design` 定时）。
- **音效**：BGM 与 SFX 分层。SFX 标记事件（转场、出现、强调），BGM 承载情绪；同一时刻不要既加音效又抬音乐。
- **画面**：换曲点可以与画面转场对齐，但不强制“每个转场都换曲”；画面切换密集的段落更适合单曲贯穿。
- **节奏**：不要为了卡音乐重拍而改变剪点；如果音乐与剪点冲突，优先改音乐位置，不改叙事节奏。

## 输出合同

- `output/bgm-plan.json`：`schema_version`、`status`、`source`、`data_at`、`missing`、`ratio`（适用时）、`arc[]`（章节情绪弧）、`candidates[]`（Pixabay 搜索词、候选链接及 `candidate_only` 状态）、`tracks[]`（仅含已取得的本地曲目及权利证据）、`cues[]`（每个 cue：`cue_id`、`chapter_id`、`start`、`end`、`track_id`、`in_point`、`out_point`、`gain_db`、`ducking{attack_ms,release_ms,min_gain_db}`、`fade_in`、`fade_out`、`transition_to_next`、`reason`）。
- `output/bgm-qc.json`：`schema_version`、`status`、`source`、`data_at`、`missing`、`checks[]`（覆盖、重叠、换曲点响度差、爆音、ducking 生效、LUFS、true peak、授权核验）、`evidence_paths[]`。

规则：

- `cues` 必须连续覆盖整片；允许设计留白，但留白要显式写成 `gap` 类型的 cue 并写理由。
- 每个 cue 必须引用已登记的 `track_id`；`tracks[].rights_status` 非 `verified` 时不得出现在 `cues` 中。
- `status=ready` 必须有 `bgm-qc.json` 的逐项检查支撑；文件存在不等于通过。

## 失败与降级

- 没有任何可用授权曲目时，只用本地 `search-pixabay` Skill 生成并记录 Pixabay 候选。该 Skill 不提供下载或授权核验；若运行时没有明确提供的授权获取能力，记录候选待取得并写 `resume_from=bgm_selection`，不得把链接当作已交付 BGM。不得通过通用网页搜索、其他网站或其他音乐搜索/provider 兜底。
- 授权信息缺失（有文件无许可证）：标 `unverified`，不得混入成片；能替换就替换，不能替换则失败。
- 音乐能力/解码失败：保留计划与已核验素材，写失败产物，`resume_from=bgm_mix`。
- 本地 `search-pixabay` Skill 不可用时，记录 `pixabay_skill_unavailable` 并写 `resume_from=bgm_selection` 的可恢复失败；不得静默切换来源。只有搜索链接、没有本地文件或权利证据时，状态必须保持待取得/未完成，不把“已生成搜索链接”当成 BGM 已完成。
- 无法测量响度：允许交付但必须标 `loudness_unverified`，不得声称符合任何响度标准。
- 无法复听：只做自动检查并明确标注“自动检查通过，人工复听未完成”。

## 质量检查

交付前逐项确认并写入 `bgm-qc.json`：

1. 覆盖：`cues` 起止连续，无意外空洞；设计留白有理由。
2. 情绪：每章音乐与 `arc[].emotion`/`energy` 一致，无风格打架。
3. 换曲：每次换曲都在章节边界或明确语义点；无爆音、无调性冲突、无节奏错位。
4. 人声：口播段音乐 -12dB 以下；ducking 生效且不抽吸；1–4kHz 已避让。
5. 响度：整片积分响度与真峰值达标，换曲点响度差 ≤ 3 LU。
6. 授权：每首曲目 `rights_status=verified`，许可证与哈希齐全。
7. 结构：无同一章内碎换曲；单曲贯穿时 loop 接缝不可听出。
8. 与画面/字幕：换曲不压关键数字与免责声明；不驱动字幕时间。
9. 候选状态：未下载的 Pixabay 候选与已授权的本地 track 分开记录，未下载候选不得出现在 `cues` 中。
10. 重复审计：比较全片 cue 的 `track_id` 与源时间区间；逐段复听重复段落，确认不是因每段从曲头重播而造成机械重复，并在 `bgm-qc.json` 记录检测结果和例外理由。
