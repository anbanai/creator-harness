## 公众号贴图文案合同

### 平台字数闸门

- `title` 是发布包的标题，含标点、空格和 emoji，硬上限为 **20 个 Unicode 字符**；目标区间为 12–18 个字符。不能靠截断解决超限，必须重写并再次确认标题仍准确对应内容。
- `content` 是发送到公众号贴图编辑器的纯文本图下注释，硬上限为 **1000 个 Unicode 字符**；计数包含正文、空行、标点、空格、emoji 和末尾公开话题标签，不包含单独的 `title` 字段。目标控制在 850–950 个字符。
- 计数前把换行统一为 `LF`，去掉首尾空白；不要把 Markdown 标记、HTML 标签或内部说明写入 `content`。以最终将要写入 `publish-package.json` 的字符串计数，不以 `content.md` 的文件字节数代替。
- 写作完成、图片生成前、交付包生成前各复核一次。任何一次超限都回到文案步骤修订；不能把超限稿交给视觉阶段，也不能让 `status=ready`。

### 可读排版

发布 caption 使用纯文本和换行，不使用 Markdown、HTML、表格或长横线分隔。排版目标是让读者在公众号编辑器和手机端都能快速扫读，不套用小红书的高密度 emoji、花式强调或装饰小标题。

- 开头先交代场景、问题或结论，让读者尽快知道这段文字在说什么。
- 正文按意思和转折自然分段，每段只推进一个主要信息动作。优先让读者在手机上容易扫读；段落长短和句数随内容决定，不为满足固定段数或句数而拆碎或扩写。若一段包含多个观点、转折或例子，再考虑拆分。
- 段与段之间保留一个空行。图片背景、编辑器字号或窄屏换行不能替代段落分隔；避免把多个论点连成一整块长文。
- 只有存在真实并列要点、步骤或对比时才用 `1.`、`2.`、`3.` 或 `①`、`②`、`③`，每项独立一行；叙事和连续解释保持自然段，不强行清单化。
- 关键转折最多用少量且语义明确的 emoji 或符号作视觉锚点。不要连续堆叠 emoji、给每段加装饰标题，或用符号替代事实和解释。
- 标签单独放在末行；正文收束与标签之间留一个空行。

`output/content.md` 保留下面三段，便于审核和人工复核：

```markdown
# 标题
<与 publish-package.title 完全一致>

## 图下注释
<将要写入 publish-package.content 的纯文本正文和标签>

## 计数复核
- title_chars: <整数>/20
- content_chars: <整数>/1000
- tags: <整数>
```

`# 标题`、`## 图下注释` 和 `## 计数复核` 只是内部文档标记，不能复制进发布包的 `title` 或 `content`。

发布 caption 的形态应接近下面这样：

```text
霜降以后，茶要换一种喝法。

天气转凉，绿茶的鲜爽会变得更轻，焙火足的乌龙和红茶更适合慢慢喝。

选茶时先看季节，再看自己的口味：想要清爽选轻焙，想要温润选足火。

一杯茶的时令感，来自茶山，也来自当下的天气。

#茶文化 #秋季喝茶 #乌龙茶 #红茶 #喝茶入门 #买茶怎么选
```

示例中的标题不包含在 caption 里；标签整行位于正文之后，并计入 `content_chars`。

### 公开话题标签

标签参考小红书的“核心大词 + 垂直场景 + 长尾意图”分层，但只保留与本稿事实直接相关的词，不声称标签会带来固定曝光。默认生成 5–8 个不重复标签，按以下顺序放在 caption 末尾，单独占一行：

1. 核心主题 1–2 个：内容究竟在讲什么，如 `#茶文化`、`#家庭收纳`。
2. 垂直场景 2–3 个：品类、季节、地域或使用场景，如 `#秋季喝茶`、`#乌龙茶`。
3. 长尾意图 2–3 个：读者正在解决的问题或想采取的行动，如 `#喝茶入门`、`#买茶怎么选`。

标签必须使用 `#标签名` 形式，标签之间用一个空格分隔；不要使用逗号、数组 JSON、`标签：` 前缀或无关热点。用户明确提供的标签原样保留，可补充相关标签，但不能删除或改写用户标签。标签本身计入 `content` 的 1000 字上限。

### 三道复核闸门

1. **写作后复核**：确认标题和 caption 已分离，统计 `title_chars`、`content_chars`，检查开头主题清楚、段落按意思组织且每段只推进一个主要信息动作、段落间有空行、列表确有并列依据、没有密集装饰，以及 5–8 个标签；超限或读起来仍像整篇长文时，先按意思拆段或精简再复核，不要求固定段数或句数。
2. **出图前锁定**：从最终 `content.md` 读取标题、正文和标签，重新统计并把同一计数写入 `content-script.md`；图片计划、封面文字和发布包只能使用这版标题，不得在后续阶段静默改名。
3. **交付前复核**：对即将写入 `publish-package.json` 的 `title` 和 `content` 原字符串重算；检查开头与段落层次清楚、段落按意思组织且每段只推进一个主要信息动作、段间空行保留、列表使用有据、没有密集 emoji/装饰分隔，标签仍在末行，且无 Markdown/HTML、无重复标签。不得用固定段数或句数作为通过条件。任一失败都写入 `output/failure-state.json`，并让 `status` 与 `readiness.status` 同为 `blocked`。

复核记录至少包含：`title_chars`、`content_chars`、`title_limit=20`、`content_limit=1000`、`tag_count`、`format_status` 和 `review_status`。不要用“已检查”代替数字或检查结论。
