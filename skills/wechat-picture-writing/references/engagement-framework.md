# 公众号贴图内容结构参考

这份参考把一篇创作者的长期实测经验整理成可复用的写作启发式。它用于选择贴图的内容角度、组织短文案和设计互动收束，不是流量保证，也不替代任务画像、事实核验、合规审核或发布包合同。不要照搬示例句式；应根据账号定位、图片事实和读者场景重新表达。

## 先判断内容的主任务

一组贴图只选一个主任务：让读者代入一种处境、得到一份可执行清单、重新看待一个常识，或感受到一个生活细节。不要为了显得丰富，把四类结构叠在同一组图里。图片和 caption 必须共享同一个中心情绪或观点，不能让文案承担图片无法证明的事实。

| 主任务 | 结构骨架 | 适合的图片与题材 | 写作重点 |
| --- | --- | --- | --- |
| 痛点共鸣 | 场景 → 未说出口的情绪 → 可复述的体会 | 情感、职场、家庭、生活处境 | 场景要具体，情绪要克制，体会要落回读者的现实 |
| 数字干货 | 问题 → 3–4 个有依据的要点 → 与主题相关的自测或讨论 | 清单、盘点、测评、步骤图 | 数字必须真实且能逐项兑现；每项只表达一个动作或判断 |
| 认知反差 | 常见看法 → 限定条件下的修正 → 新视角 → 开放讨论 | 成长、关系、工作、观点配图 | 反差要有理由，不能用绝对化或故意制造焦虑替代论证 |
| 小事共情 | 可见细节 → 感官或氛围 → 轻量升华 | 美食、街景、随拍、日常记录 | 先写看得见、听得到、感受到的东西，再给克制的情绪落点 |

## 写作流程

1. 从图片、任务画像和主题事实中提取一个具体场景或问题，标出读者可能识别的情绪或需求。
2. 选择上表的一种骨架，并写出一句中心判断。中心判断必须能被图片或任务素材支持。
3. 把正文拆成短句和短段：一段只推进一个动作，段落之间保留空行。口语化不等于随意堆叠感叹词，短句也要有因果和信息。
4. 标题先抓住场景、痛点、反差或结果，再检查是否准确。贴图标题可以偏短（常见试验区间为 6–12 个字符），但现行发布合同的 20 字硬上限和 12–18 个字符目标优先；不要为了短而截断关键限定。
5. 结尾只在确有讨论价值时提问，例如让读者分享经历、选择项或判断标准。问题必须承接正文，不能用空泛的“你怎么看”制造互动。

## 质量闸门

- 首屏读者即使还没看完整组图，也能判断这段文字在说什么；caption 仍须符合 `format-and-tags.md` 的纯文本、分段和标签合同。
- 每张图或每个页面只承担一个信息动作；不要把长段落缩小后塞进图片，也不要用重复金句凑图数。
- 数字、测评结果、对比结论和“半个月见效”等承诺必须有任务素材或可靠来源；没有依据就改成经验表达或删除。
- 共鸣来自具体细节和真实处境，不靠“所有人都”“一定”“最好的”等绝对化表述。
- 互动问题、情绪句和升华句都服务于中心主题；删掉后不影响事实和可读性的装饰句优先删除。
- 经验文章关于推荐机制的判断只能作为待验证假设，不能在交付文案中承诺曝光、完读率、评论量或“平台必推”。

## 与视觉阶段的衔接

把选定的结构写入 `output/content-dna.json` 或 `output/image-plan.md` 的决策记录，至少说明 `primary_formula`、`scene_or_question`、`core_emotion_or_need` 和 `reader_action`。视觉计划应让画面先传达场景或细节，再用少量文字补充观点；不能用文案里的反差或金句掩盖画面主体缺失。生成图后仍按 Agent 的逐图 `analyze_image` 合同审核文字安全区、主体关系和内容贴合度。
