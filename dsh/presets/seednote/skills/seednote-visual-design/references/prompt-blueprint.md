## 这份参考解决什么问题

工业级图片提示词的差异不在于“写得越长越好”，而在于把不同种类的决定分开，并在生成前检查它们是否互相冲突。一个可复用的 Seednote prompt 由以下九个槽位组成：

1. **页面契约**：这张图在整篇笔记中的角色、阅读目标、平台和比例。
2. **文字契约**：允许出现的可见文字、阅读顺序、行数、文字安全区和层级。
3. **主体事实**：画面中必须出现的对象、材质、状态、动作和对象之间的关系。
4. **构图地图**：视角、景别、主体区域、文案区域、留白、对齐和信息块顺序。
5. **艺术指导**：媒介、纸张/表面、色板、字体气质、批注和图标语言。
6. **光线与质感**：光线方向、软硬、色温、阴影、景深和细节优先级。
7. **跨页连续性**：整组图片必须保持的风格锚点，以及本页必须变化的场景或焦点。
8. **负面约束**：不得出现的文字、对象、动作、版式和平台风险。
9. **输出与验收**：比例、移动端可读性、清晰度、文件角色和可观察的通过条件。

不要为了模仿“上千个提示词”而填充同义形容词。缺少一个关键槽位，比少写几十个风格词更容易造成失败。

## 何时读取

在写 `image-plan.md` 时用它补齐每页的视觉决策；在写 `image-prompts.md` 和调用 `generate_image` 前，再用它把每页计划编译成独立 prompt。`content.md`、`cover.md` 和 `tail.md` 只提供页面类型的默认值，用户或 `image-plan.md` 的明确字段优先。

## 编译顺序与优先级

最终 prompt 按下面顺序组织，避免把审美描述放在硬约束前面稀释它们：

```text
页面契约 → 文字契约 → 构图地图 → 主体事实 → 艺术指导 → 光线质感
→ 跨页连续性 → 负面约束 → 输出与验收
```

发生冲突时按以下优先级处理：

1. 用户锁定的文字、主体事实、禁止项和比例。
2. `image-plan.md` 的页面职责、布局和验收标准。
3. 当前页面的可读性与移动端安全区。
4. 项目共享风格块。
5. 可选的氛围和装饰。

通用模板不能覆盖前四项。若计划只给了“真实照片背景”，但共享风格块明确是“新中式水彩、宣纸纹理”，把它编译为“有真实物理关系的茶席场景 + 水彩/宣纸媒介”，不要机械重复两个互相拉扯的媒介词。

不要把整篇正文原样塞入每张图的 prompt。只传入当前页的 `page_scope`，并明确“不得引入其他页面的信息、茶类、季节或文字”。这样可以减少模型把下一页内容画进当前页。

## 文字契约

图片模型对中文文字的稳定性有限，文字要求必须像数据清单一样写，不能只写“文字清晰”：

- 从“必须出现文字”生成唯一的可见文字白名单；不得由模型补充副标题、标签、品牌名、页码、水印或装饰标语。
- 每条文案用全角引号「」包裹，按最终阅读顺序单独列出；禁止合并、拆分、改字、改标点或同义改写。
- 计划要求可见的徽章、箭头标签或短字样，也必须单独加入白名单。例如徽章需要显示“一”“二”“三”，就写成“可见徽章文字：一、二、三”；它们不是 prompt 的列表编号。
- prompt 中的 `1.`、`2.`、`3.` 只是元指令，除非白名单明确要求，否则不能出现在画面。
- “模糊不可辨识的红色装饰印章”只允许作为无可读字形的色块/印面；不能生成伪汉字或可辨识印文。
- 文字较多时优先调整信息块尺寸、间距和背景对比，不要擅自压缩或改写用户锁定文案。
- 文字验收同时看**内容正确、顺序正确、位置不被主体遮挡、缩略图可读**四件事；仅有“风格统一”不能通过。

提示词可以提高文字命中率，不能把生成模型变成确定性排版引擎。对逐字准确、数量多或含关键参数的文案，若运行环境提供文字合成能力，优先生成无文字底图后再按白名单叠字；否则必须用 `analyze_image` 做逐字观察并按可见错误重试，不能仅凭 prompt 声称文字已通过。

## 构图地图

每页至少写清楚以下可观察关系。坐标使用相对区域即可，不要求像素级数值：

| 字段 | 要回答的问题 |
| --- | --- |
| `camera` | 俯拍、平视、三分之四视角还是局部微距？ |
| `shot` | 全景、桌面中景、主体特写还是物件组？ |
| `focal_area` | 观众第一眼看到什么，位于左/中/右、上/中/下哪个区域？ |
| `text_zone` | 文字放在哪里，是否有连续、干净、足够对比的安全区？ |
| `layout_map` | 信息块按行、列、卡片、流程或标注如何排列？ |
| `negative_space` | 哪些区域明确留空，避免主体或装饰侵入？ |
| `reading_order` | 观众先看标题、再看主体，还是按一→二→三阅读？ |

封面默认一个主焦点；内容图可以有多个信息块，但每个信息块只能承担一个信息点。对比双栏必须写清左右/上下分别代表什么，编号清单必须写清徽章、步骤和对应主体的关系，不能只写“信息图风格”。

## 主体事实、艺术指导与光线

把“视觉主体”继续拆成可观察事实：

- 对象：茶罐、干茶碟、盖碗、茶汤杯、冷藏盒等具体对象。
- 状态：干燥/结块/发黏、汤色浑暗、罐盖打开或密封等可见状态。
- 关系：哪个对象对应哪条信息，不能只把几个物件随意摆在一起。
- 动作：闻香、倒茶、收纳等动作必须符合当页结论，不能产生误导性冲泡示范。

艺术指导只保留能改变画面的词：媒介和表面（例如水彩、宣纸纹理）、3–5 个主色/强调色、字体气质、批注/图标语言。光线写方向、软硬和色温，例如“左上方柔和日光、轻微纸面阴影、茶汤高光可见”。少写同义的“高级、精致、好看”。

## 页面类型默认值

这些是可调整的默认值，不是对所有任务的硬编码：

### 封面

- 页面目标：缩略图中快速读出一个点击理由。
- 构图：单一主体焦点，文案位于连续安全区，主体与文字不要互相遮挡。
- 信息量：只保留主文案和必要的一个辅助信息；正文知识点放到内容图。
- 验收：缩小到信息流卡片后，主题、主体和主文案仍能对应。

### 内容图

- 页面目标：让读者按明确顺序理解 2–4 个信息点。
- 构图：先确定布局地图，再把每个信息点绑定到一个主体、图标或局部状态。
- 信息量：保持计划的原文案；通过卡片间距、字号和留白控制密度。
- 验收：每条文字都能找到对应的视觉证据，且不存在跨页信息。

### 尾图

- 页面目标：按计划完成关注、评论或流量收束，不新增正文事实。
- 构图和文字：使用独立的尾图计划；不得把封面或内容页的整套文字复制过来。

## 可复用的最终 prompt 骨架

把大括号替换为当前页事实后再调用 `generate_image`。空字段要删除，不能填“无”：

```text
页面契约：这是种草笔记的 {封面/内容图/尾图}，页面职责是 {page_goal}；输出比例为 {aspect_ratio}，面向手机信息流缩略图阅读。

文字契约：画面只允许出现以下可见文字，按顺序逐条、原样渲染：{visible_text_whitelist}。
文字布局为 {text_layout}，文字安全区为 {text_zone}，字号/对比度以缩略图可读为准。不得出现任何未列入白名单的文字、字母、拼音、页码、水印或伪词。

构图地图：{camera}，{shot}；第一视觉焦点是 {focal_area}；{layout_map}；保留 {negative_space}；阅读顺序为 {reading_order}。

主体事实：必须出现 {subjects}；它们分别呈现 {states}，并与信息点建立这些关系：{subject_relations}。只表现 {allowed_action}，不得表现 {forbidden_action}。

事实依据原句：{must_match_excerpts}。这些原句仅用于约束画面事实，不得渲染为图片文字。

艺术指导：{medium_and_surface}；共享风格锚点为 {style_anchors}；本页变化为 {page_variation}；批注/图标语言为 {annotation_language}。

光线与质感：{lighting}；强调 {material_details}；避免塑料感、无关反光和主体糊成一团。

禁止项：{negative_constraints}。不得带入其他页面的 {out_of_scope_items}。

输出验收：主体、文字、布局和页面职责必须同时满足 {acceptance_criteria}；画面干净、无水印、无额外文字，缩小查看仍可读。
```

## 示例：把茶叶保质期规划编译成 prompt 槽位

下面只示范如何拆槽位，不把这组文案变成其他任务的固定模板：

```text
页面契约：内容图，职责是让读者按一→二→三判断茶叶是否需要放弃；3:4。
文字契约：可见文字为「三步判断」「看干茶：白毛绿毛、结块发黏」「闻香气：霉味、酸馊味、杂味」「泡一杯：汤色浑暗、发酸发涩」；可见徽章文字为“一、二、三”；除此之外不出现文字。
构图地图：45°桌面俯拍，三段纵向信息卡；徽章位于每段左上，干茶/闻香/茶汤依次绑定三段主体；右侧和卡片间保留浅色宣纸留白。
主体事实：干茶碟呈现可观察的白毛绿毛与结块发黏状态；盖碗与鼻息动作只表达闻香；茶汤杯呈现浑暗色泽；不画饮用或治疗效果。
艺术指导：新中式水彩叠加宣纸纹理，米白/浅杏底，茶褐主色，灰橄榄绿点缀，圆形徽章和不可辨识红色装饰印章；本页用手绘放大镜批注区分三种观察动作。
禁止项：英文、拼音、阿拉伯数字、伪词、额外副标题、其他茶类或季节、医疗功效承诺、把三条文案合成文字墙。
```

## 生成前自检

- 每个页面是否只有一个明确目标？
- `visible_text_whitelist` 是否覆盖了计划要求的所有可见字（包括徽章字），且没有把 prompt 编号误当成画面文字？
- 每条文案是否绑定了位置、顺序和视觉证据？
- 是否写出了主体状态/关系，而不只是物件名？
- 是否写出了镜头、景别、焦点、文字安全区和布局地图？
- 共享风格是否被压缩成少量稳定锚点，并明确了本页变化？
- 是否显式排除了其他页面信息和模型可能补写的文字？
- 缩略图阅读与逐张 `analyze_image` 的验收条件是否可观察？

只有在这些问题都能从 prompt 中回答时，才把它记录为最终 prompt。提示词长度本身不是通过条件。
