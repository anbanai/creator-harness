# 创作决策框架

这是一套质量检查骨架，不是固定问卷。它保证作品开始生产前，最影响成品质量的决定已经收敛，同时允许问题顺序、文案和选项随上下文变化。

## 必须收敛的决定

1. **目标**：本次作品要解决什么问题，或希望读者/观众完成什么变化。
2. **话题**：作品具体讨论的主题、场景或问题。话题不是 `content_type`，也不是标题。
3. **角度**：从哪个受众痛点、冲突、经验、证据或观点切入。
4. **表达形式**：教程、案例、清单、对比、故事、观点拆解等最适合承载当前角度的方式。
5. **必要输入**：只补齐会影响事实准确、合规或成品可用性的素材、案例、来源、限制和验收标准；不存在这类缺口时无需额外追问。

`target_audience`、风格、平台、偏好和长期边界优先从 Server 注入的项目画像继承。用户没有明确要求临时改变时，不重新确认这些六维信息；临时调整只能进入当前计划，不得写回画像。
最终 ready 计划中的 `profile_context` 必须列出本次实际沿用的画像信息，`temporary_overrides` 必须列出用户明确提出的本次调整；两者均无内容时仍提交空数组。来源标注不需要向用户再次确认画像。

## 选择问题还是开放输入

- 用户已表达事实、经历、素材或边界时直接采用，不再重复提问。
- 需要用户在可比较方案中做决定时，调用 `AskUserQuestion` 给出 3-5 个基于当前上下文生成的选项。
- 每批只推进一个决定；最多一个选项标记 `recommended: true`，并说明推荐依据。推荐项只作建议，不能替用户选择。
- 每个选项批次保留“其他/自定义”；用户说“帮我推荐”时，Agent 可以选择一个建议并说明理由，仍等待用户确认。
- 只有无法合理预设的业务事实、真实案例、素材细节、来源或风险边界才要求用户输入文字。

## 推荐顺序

通常先确认目标，再按缺口依次确认话题、角度和表达形式，最后补齐必要素材、事实和边界。已明确的决定直接跳过；如果用户已经给出话题，就从角度开始；如果用户没有方向，可以先给动态话题候选。不要为了完成顺序而重复询问。

标题、详细大纲、正文措辞、镜头编排、配图提示词和内部执行参数由后续内容 Agent 自主决定。最终计划只需提供足够的方向、约束和验收标准。
